# Claude Code через Telegram

Когда Claude Code нужно разрешение на действие, вопрос приходит в Telegram с
кнопками. Отвечаете с телефона — Claude Code продолжает работу. Можно разрешить
один раз, до конца сессии или навсегда, запретить с причиной, а в конце получить
ответ целиком и написать, что делать дальше.

Если ответа нет 5 минут, пропал интернет, бот недоступен или настройки пустые —
скрипт молча завершается, и вопрос задаётся обычным способом в терминале.
**Claude Code не зависает и не ломается ни при каком раскладе.**

```
🔔 Cou-cou analog · #a4f2 · сессия 9bd1
🔧 Bash
    git push origin main
💬 Отправить коммиты на сервер
♾ «Всегда» добавит правило: git push *
📁 C:\Users\Neo\Desktop\Python\projects\Cou-cou analog

[ ✅ Разрешить ]        [ ❌ Запретить ]
[ ⏳ До конца сессии ]  [ ✏️ Запретить с причиной ]
[ ♾ Всегда: git push * ]
```

Нужен только Python 3.8+ и ничего больше: ни одной устанавливаемой библиотеки.

## ⚠️ Прежде чем ставить

**Содержимое запросов уходит на серверы Telegram.** В сообщении видны команды,
пути к файлам и превью правок — то есть фрагменты вашего кода. Для личных
проектов это обычно неважно, для рабочего или чужого кода решайте осознанно.
Безопасный список (`safelist.txt`) и сужение `matcher` помогают уменьшить то,
что уходит наружу.

Остальное про безопасность — в конце файла.

## Установка

### 1. Бот

Напишите [@BotFather](https://t.me/BotFather) → `/newbot`. Полученный токен
впишите в `.env` (скопируйте из `.env.example`), строка `TG_TOKEN=`.

### 2. Свой chat_id

Откройте бота в Telegram, нажмите «Start», затем:

```powershell
python get_chat_id.py
```

Показанный номер впишите в `.env`, строка `TG_CHAT_ID=`.

### 3. Хуки

Добавьте в `~/.claude/settings.json` (на Windows это
`C:\Users\<вы>\.claude\settings.json`) раздел `hooks`. Пути замените на свои.

```json
"hooks": {
  "PermissionRequest": [
    {
      "matcher": ".*",
      "hooks": [
        {
          "type": "command",
          "command": "C:\\Users\\Neo\\AppData\\Local\\Programs\\Python\\Python312\\python.exe",
          "args": ["C:\\путь\\к\\проекту\\tg_approve.py"],
          "timeout": 360,
          "statusMessage": "Жду одобрения в Telegram..."
        }
      ]
    }
  ],
  "Stop": [
    {
      "hooks": [
        {
          "type": "command",
          "command": "C:\\Users\\Neo\\AppData\\Local\\Programs\\Python\\Python312\\python.exe",
          "args": ["C:\\путь\\к\\проекту\\tg_notify.py"],
          "timeout": 130
        }
      ]
    }
  ],
  "SessionStart": [
    {
      "hooks": [
        {
          "type": "command",
          "command": "C:\\Users\\Neo\\AppData\\Local\\Programs\\Python\\Python312\\python.exe",
          "args": ["C:\\путь\\к\\проекту\\tg_session.py"],
          "timeout": 20
        }
      ]
    }
  ]
}
```

Пояснения:

- Путь к Python указывайте полностью. Не `python` из PATH и **не**
  `WindowsApps\python3` — последнее заглушка от Microsoft Store.
- В JSON обратные слэши удваиваются (`\\`).
- Программа (`command`) и путь к скрипту (`args`) разделены — так пробелы в
  пути не требуют кавычек.
- `timeout` у `PermissionRequest` должен быть больше `CC_TG_TIMEOUT` (по
  умолчанию 300 с), у `Stop` — больше `CC_TG_FOLLOWUP_WAIT` (по умолчанию 90 с).
- `matcher: ".*"` — на все инструменты. Чтобы сообщений было меньше, сузьте до
  `"Bash|PowerShell|Edit|Write"`.
- `Stop` и `SessionStart` необязательны, но полезны.

На macOS и Linux то же самое, только пути обычные:
`"command": "/usr/bin/python3"`, `"args": ["/home/вы/проект/tg_approve.py"]`.

### 4. Перезапустите Claude Code

Настройки читаются при старте. В уже запущенной сессии новые хуки не появятся:
откройте `/hooks` (это перечитывает конфиг) или перезапустите.

## Важно: режим разрешений

Событие `PermissionRequest` возникает **только когда Claude Code собирался
спросить вас**. В режимах, которые не спрашивают, запросы в Telegram приходить
не будут:

| Режим | Одобрения в Telegram |
|---|---|
| `default` | работают |
| `plan` | работают для действий, которые всё же требуют разрешения |
| `acceptEdits` | не работают для правок файлов, работают для команд |
| `auto` | **не работают** — решает встроенный классификатор |
| `bypassPermissions` | **не работают** — разрешено всё |

Переключить режим: `Shift+Tab`. Текущий видно в строке состояния и в `/status`.
Хук `SessionStart` при старте предупредит, если режим «молчащий».

## Кнопки

| Кнопка | Что делает |
|---|---|
| ✅ Разрешить | разрешает один раз |
| ❌ Запретить | отменяет действие |
| ⏳ До конца сессии | запоминает локально: такие же запросы в этой сессии одобряются сами |
| ✏️ Запретить с причиной | просит написать причину ответом на сообщение; текст уходит Claude, и он может исправиться |
| ♾ Всегда | добавляет постоянное правило разрешений. Спрашивает подтверждение вторым шагом, потому что правило остаётся навсегда |

Опасным командам (`rm`, `del`, `mv`, `curl`, `shutdown`, `chmod` и ещё около
двадцати) кнопка «Всегда» не предлагается вообще.

После нажатия сообщение превращается в «✅ Разрешено в 11:42», кнопки исчезают.

## Ответ с телефона

Хук `Stop` присылает ответ Claude целиком (длинный — несколькими сообщениями,
с разметкой: код моноширинным, таблицы не разъезжаются). Если включить в `.env`
`CC_TG_FOLLOWUP=1`, под ответом появится приглашение написать, что делать
дальше. Ответьте на это сообщение — и ваш текст станет следующей инструкцией:
Claude не завершит ход, а продолжит работу.

Под приглашением есть кнопка «⏹ Не жди меня»: нажмите, и ход завершится сразу, не тратя окно впустую. Поэтому окно можно делать длинным без неудобств.

Учитывается время отправки сообщения, а не получения: написанное до приглашения не подхватится как ответ.

Ограничения, чтобы это не превратилось в бесконечный цикл: не больше
`CC_TG_FOLLOWUP_MAX` продолжений подряд (по умолчанию 3), ожидание
`CC_TG_FOLLOWUP_WAIT` секунд (по умолчанию 90), и продолжение случается только
если человек действительно что-то написал. После паузы без ответа бюджет
продолжений обновляется.

## Стикеры

К каждому событию можно привязать свой стикер — всего их 24, от «спрашиваю про
опасную команду» до «заснул, время вышло». Полный список с описанием поз и
запросами для ИИ — в [`stickers_brief.md`](stickers_brief.md).

Пак через [@Stickers](https://t.me/Stickers) собирать **не нужно**: Telegram
принимает PNG 512×512 прямо в `sendSticker` и сам возвращает идентификатор.

```powershell
# 1. Нарезать лист со стикерами на отдельные файлы 512×512
python make_stickers.py stiker_pack/лист.png

# 2. Посмотреть, что получилось
python make_stickers.py --contact stiker_pack/ready

# 3. Назвать файлы по событиям (ask_bash.png, allowed.png, …) и загрузить
python get_sticker_ids.py --upload stiker_pack/ready

# перезалить только исправленные
python get_sticker_ids.py --upload stiker_pack/ready denied timeout
```

`make_stickers.py` работает без сторонних библиотек: PNG разбирается через
`zlib`, стикеры ищутся как связные области непрозрачных пикселей, слипшиеся
соседи разрезаются по самому пустому столбцу между ними.

Если пак уже собран в Telegram, есть и второй путь: `python get_sticker_ids.py
--assign` — скрипт по очереди просит прислать стикер для каждого события.

`stickers.json` создаётся локально при первой загрузке и в репозиторий не попадает: идентификаторы привязаны к конкретному боту и у других не работают.

Пока `stickers.json` пустой, стикеры не отправляются вообще. Как только там
появился хотя бы один идентификатор, отправка включается сама. Управление —
`CC_TG_STICKERS` в `.env`: `all`, `decisions` или `off`.

## Настройки `.env`

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `TG_TOKEN` | — | токен бота от @BotFather |
| `TG_CHAT_ID` | — | ваш `chat_id`, только от него принимаются нажатия |
| `CC_TG_TIMEOUT` | `300` | сколько секунд ждать нажатия |
| `CC_TG_QUIET` | — | тихие часы, например `23:00-08:00`: в это время ничего не отправляется, вопросы идут в терминал |
| `CC_TG_FOLLOWUP` | `0` | `1` — разрешить отвечать Claude с телефона |
| `CC_TG_FOLLOWUP_WAIT` | `90` | сколько секунд ждать ваш текст. Должно быть меньше `timeout` хука `Stop` в settings.json |
| `CC_TG_FOLLOWUP_MAX` | `3` | сколько продолжений подряд разрешено |
| `CC_TG_ANSWER_LIMIT` | `10000` | сколько символов ответа присылать (`0` — без предела) |
| `CC_TG_STICKERS` | авто | `all`, `decisions` или `off` |
| `CC_TG_DEBUG` | `0` | `1` — писать подробности в поток ошибок |

Переменная окружения перекрывает `.env`, в том числе пустым значением:
`TG_TOKEN= claude` запускает Claude Code с выключенными одобрениями.

## Безопасный список

Команды из `safelist.txt` одобряются сразу на компьютере, без сообщения в
телефон — чтобы `git status` не присылал уведомление сто раз в день. Правила:

- совпадение по началу команды: `git status` покрывает `git status --short`,
  но не `git statuses`;
- если в команде есть `&&`, `;`, `|`, `` ` ``, `>`, `<`, `$(` — список **не**
  применяется, чтобы `git status && rm -rf x` не проскочил;
- `cat`, `head`, `tail` намеренно отсутствуют: иначе чтение любого файла,
  включая `.env` и приватные ключи, одобрялось бы молча.

Список действует только при заполненном `.env`. Если токен не настроен, скрипт
вообще ничего не решает — все вопросы идут в терминал.

## Проверка

Автотесты (сеть не нужна, настоящие файлы не трогаются):

```powershell
python -m unittest discover -s tests -v
```

Ручная проверка живьём:

```powershell
# 1. Обычный путь: придёт сообщение, нажмите «Разрешить»
Get-Content tests\payload_bash.json -Raw | python tg_approve.py
# ожидаем: {"hookSpecificOutput": {"hookEventName": "PermissionRequest", ...}}

# 2. Запрет с причиной: нажмите «✏️ Запретить с причиной» и ответьте текстом
Get-Content tests\payload_edit.json -Raw | python tg_approve.py

# 3. Безопасный список: мгновенный allow, в Telegram ничего
Get-Content tests\payload_safe.json -Raw | python tg_approve.py

# 4. Таймаут, укороченный до 15 секунд — кнопку не нажимать
$env:CC_TG_TIMEOUT=15
Get-Content tests\payload_bash.json -Raw | python tg_approve.py
$env:CC_TG_TIMEOUT=$null

# 5. Выключенный бот: пусто и быстрый выход
$env:TG_TOKEN=""
Get-Content tests\payload_bash.json -Raw | python tg_approve.py
$env:TG_TOKEN=$null

# 6. Два запроса одновременно: придут два сообщения, нажмите в любом порядке
Start-Job { Set-Location $using:PWD; Get-Content tests\payload_bash.json -Raw | python tg_approve.py }
Start-Job { Set-Location $using:PWD; Get-Content tests\payload_edit.json -Raw | python tg_approve.py }
Get-Job | Wait-Job | Receive-Job
```

После каждого запуска `$LASTEXITCODE` должен быть `0`.

## Если что-то не работает

1. **Режим разрешений.** Самая частая причина «ничего не приходит» — режим
   `auto` или `bypassPermissions`. Смотрите таблицу выше.
2. **Журнал.** `decisions.jsonl` — по строке на каждый запрос, с причиной:
   `safelist`, `session_cache`, `telegram`, `telegram_reason`, `timeout`,
   `quiet_hours`, `send_failed`, `error`.
3. **Подробности.** Поставьте `CC_TG_DEBUG=1` в `.env` — скрипт начнёт писать,
   что происходит, в поток ошибок. На решения это не влияет.
4. **Хук не вызывается.** `claude --debug` показывает запуск хуков и их вывод.
   Проверьте, что `settings.json` — корректный JSON и путь к Python существует.
5. **Сообщения не приходят.** Откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getMe`. И убедитесь, что вы нажали
   «Start» у бота — без этого бот не имеет права вам писать.

## Как устроены одновременные запросы

Claude иногда вызывает несколько инструментов за раз, и скрипт запускается в
нескольких копиях. Telegram отдаёт нажатия только одному слушателю, поэтому
копии договариваются через файлы в `%TEMP%\cc-tg-approve\` (на macOS и Linux —
`/tmp/cc-tg-approve/`):

| Файл | Зачем |
|---|---|
| `poll.lock` | кто его создал, тот и опрашивает Telegram. Если процесс умер, флажок снимается: по времени или по проверке, что такого процесса больше нет |
| `offset.txt` | номер последнего обработанного события |
| `cb-<номер>.json` | «полочка»: чужое нажатие, которое заберёт адресат |
| `text-inbox.json` | входящие текстовые сообщения |
| `session-<id>.json` | что разрешено до конца сессии |

Ничего не теряется: процесс, вытащивший чужое нажатие, кладёт его на полочку,
а не выбрасывает.

Один бот рассчитан на одну машину. Если запускать его с двух компьютеров
одновременно, они начнут разбирать нажатия друг у друга — сделайте второго бота.

## Безопасность

- `.env` в `.gitignore` — токен не попадёт в репозиторий.
- Нажатия принимаются **только** от вашего `chat_id`; постороннему бот ответит
  «нет доступа». Но тот, у кого есть токен, сможет **читать** всё, что бот
  присылает, — то есть ваши команды и фрагменты кода. Храните токен как пароль,
  а при утечке делайте `/revoke` у @BotFather.
- Проверяется и номер запроса, поэтому нажатие на старое сообщение в истории
  чата не повлияет на новый запрос.
- Разблокированный телефон = доступ к одобрениям. Поэтому «Всегда» требует
  подтверждения вторым шагом, а опасным командам не предлагается вовсе.
- Кнопка «Всегда» для `python *` или `node *` фактически разрешает запуск
  любого скрипта. Если сомневаетесь — «До конца сессии» безопаснее.
